# mysql-mcp-go

[![test](https://github.com/andresudi/mysql-mcp-go/actions/workflows/test.yml/badge.svg)](https://github.com/andresudi/mysql-mcp-go/actions/workflows/test.yml)

A small [MCP](https://modelcontextprotocol.io) server, written in Go, that lets Claude (or any
MCP client) explore and query a MySQL database **read-only**. It is built to be safe to point
at a real database: the server refuses to start unless its MySQL user can only read, and no
tool call can change data or schema.

**Demo (51 s):** [watch on Loom](https://www.loom.com/share/3f7ba8e362324af5bd66cb53e52a5344)

## Tools

| Tool | Input | Output |
|------|-------|--------|
| `list_tables` | none | tables in the connected database: name, estimated row count, comment |
| `describe_table` | `table` | columns (name, type, nullable, default, key) and indexes |
| `query` | `sql` | `{columns, rows, row_count, truncated}` for one read statement |

Example `query` result for "Which project has the most overdue tasks, and who owns them?":

```json
{
  "columns": ["project", "owner", "overdue"],
  "rows": [
    ["Billing migration", "Ben Lindqvist", 22],
    ["Customer portal", "Ava Moreau", 13],
    ["Mobile app", "Hiro Okafor", 11]
  ],
  "row_count": 3,
  "truncated": false
}
```

Integers and floats come back as JSON numbers. `DECIMAL`, dates, text and binary columns come
back as strings, so no precision is lost. `NULL` is `null`.

## Quick start

You need Go 1.25+ and Docker.

```sh
git clone https://github.com/andresudi/mysql-mcp-go
cd mysql-mcp-go
docker compose up -d --wait            # MySQL 8.0 on 127.0.0.1:3316, sample data loaded
go build -o mysql-mcp ./cmd/mysql-mcp
claude mcp add mysql -e MYSQL_DSN='mcp_ro:mcp_ro@tcp(127.0.0.1:3316)/demo' -- "$PWD/mysql-mcp"
```

Then start Claude Code and ask: *"Which project has the most overdue tasks, and who owns
them?"*

The sample database is a fictional project tracker: `users` (50), `projects` (8), `tasks`
(300) and `comments` (600). It is generated by [`testdata/seed.sql`](testdata/seed.sql), so
every fresh container has the same data. The compose file's passwords (`root`/`root` and
`mcp_ro`/`mcp_ro`) are for local use only.

### Demo script (60–90 s)

1. Start the database and register the server, with the audit log in a file you can show.
   Claude Code does not display a server's stderr.

   ```sh
   docker compose up -d --wait
   claude mcp add mysql \
     -e MYSQL_DSN='mcp_ro:mcp_ro@tcp(127.0.0.1:3316)/demo' \
     -e MCP_AUDIT_LOG=/tmp/mysql-mcp-audit.log \
     -- "$PWD/mysql-mcp"
   ```

2. Ask Claude: *"Which project has the most overdue tasks, and who owns them?"* It typically
   lists the tables, describes `tasks`, then queries. Expected answer: Billing migration,
   owned by Ben Lindqvist, with 22 overdue tasks on the day the database is seeded. The count
   grows as days pass; `docker compose down -v && docker compose up -d --wait` reseeds it.
3. Ask Claude: *"Use the query tool to run exactly this: DELETE FROM tasks WHERE project_id = 3
   AND status <> 'done' AND due_date < CURDATE()"*. The server refuses. Show the line it logged:

   ```sh
   grep refused /tmp/mysql-mcp-audit.log | tail -1
   ```

   Search for `refused` rather than taking the last line. Claude often runs a `SELECT` afterwards
   to confirm nothing was deleted, and that becomes the newest line.

   Ask for the statement directly. With a softer "Delete those overdue tasks.", Claude reads the
   tool description and declines without calling the tool, so nothing is logged.
4. Try to start the server as root. It refuses:

   ```sh
   MYSQL_DSN='root:root@tcp(127.0.0.1:3316)/demo' ./mysql-mcp
   ```

### Claude Desktop

Add the server to `claude_desktop_config.json` (Settings → Developer → Edit Config), using the
absolute path to the binary:

```json
{
  "mcpServers": {
    "mysql": {
      "command": "/absolute/path/to/mysql-mcp",
      "env": { "MYSQL_DSN": "mcp_ro:mcp_ro@tcp(127.0.0.1:3316)/demo" }
    }
  }
}
```

### Your own database

Create a user that can only read one schema:

```sql
CREATE USER 'mcp_ro'@'%' IDENTIFIED BY 'choose-a-password';
GRANT SELECT, SHOW VIEW ON your_database.* TO 'mcp_ro'@'%';
```

Grant on one schema, not `*.*`. A server-wide `SELECT` still passes the startup check, since it
is read-only, but it can read MySQL's own system tables, including password hashes in
`mysql.user`. Anything this user can read can end up in the model's context, so leave out
tables you would not paste into a chat.

## Configuration

| Variable | Default | Meaning |
|----------|---------|---------|
| `MYSQL_DSN` | required | [go-sql-driver DSN](https://github.com/go-sql-driver/mysql#dsn-data-source-name), e.g. `mcp_ro:mcp_ro@tcp(127.0.0.1:3316)/demo`. Must name a database. |
| `MCP_MAX_ROWS` | `200` | row cap per `query`; more rows set `truncated: true` |
| `MCP_TIMEOUT_MS` | `5000` | `MAX_EXECUTION_TIME` per `query` |
| `MCP_AUDIT_LOG` | stderr | file to append the audit log to |

stdout carries the MCP protocol and nothing else. Errors and the audit log go to stderr or the
audit file.

## Safety model

There are four layers. Only the first is the security boundary; the other three give earlier,
clearer errors and limit resource use.

1. **Database privileges (the boundary).** At startup the server runs
   `SHOW GRANTS FOR CURRENT_USER()`. It exits with a clear message unless every grant is
   `SELECT`, `SHOW VIEW` or `USAGE`. It fails closed: `ALL PRIVILEGES`, `INSERT`, `FILE`,
   `EXECUTE`, role grants, `WITH GRANT OPTION`, column-level grants, partial revokes and any
   line it cannot parse all stop it.

   ```
   $ MYSQL_DSN='root:root@tcp(127.0.0.1:3316)/demo' ./mysql-mcp
   mysql-mcp: refusing to start: the MySQL user must hold only SELECT and SHOW VIEW: grant is not a plain SELECT/SHOW VIEW grant: "GRANT SELECT, INSERT, UPDATE, DELETE, ... ON *.* TO `root`@`%` WITH GRANT OPTION"
   ```

2. **Statement allow-list.** After leading whitespace and comments are stripped, the statement
   must start with `SELECT`, `WITH`, `SHOW`, `DESCRIBE`/`DESC` or `EXPLAIN`. A leading
   executable comment (`/*! … */`) is rejected, because MySQL runs its contents. The driver's
   `multiStatements` option is always forced off, so `SELECT 1; DROP TABLE t` is a syntax
   error. `WITH … DELETE` passes this check by design; layer 1 stops it.

3. **Per-query limits.** Each `query` runs inside `START TRANSACTION READ ONLY`, sets
   `MAX_EXECUTION_TIME`, reads at most `MCP_MAX_ROWS + 1` rows to set `truncated`, and is
   always rolled back. MySQL applies `MAX_EXECUTION_TIME` to `SELECT` statements only.

4. **Audit log.** Every tool call writes one JSON line, including refused calls:

   ```json
   {"time":"2026-10-12T14:18:37.209Z","tool":"query","sql":"DELETE FROM tasks WHERE due_date < CURDATE()","row_count":0,"duration_ms":0,"error":"refused: only read statements are allowed (SELECT, WITH, SHOW, DESCRIBE/DESC or EXPLAIN); this server cannot change data or schema"}
   ```

[`internal/db/query_attack_test.go`](internal/db/query_attack_test.go) sends crafted writes
straight to the database layer, skipping the allow-list. It checks that every table's row count
is unchanged. The statements include `DROP TABLE`, `WITH … DELETE`, `EXPLAIN ANALYZE DELETE`,
`SELECT … INTO OUTFILE`, a stacked `SELECT 1; DROP TABLE users` and `/*!50000 DROP TABLE users */`.

### Rejected approaches

**A read-only transaction on its own.** In MySQL, DDL causes an implicit commit, so
`START TRANSACTION READ ONLY; DROP TABLE t;` ends the transaction and then drops the table.
Running the attack test as root shows this: the read-only transaction blocks `DELETE`, `UPDATE`
and `INSERT` (error 1792), but `CREATE TABLE` goes through. Only privileges stop that, which is
why layer 1 is the boundary.

**Parsing SQL to decide what is safe.** A keyword check can be fooled by comments, string
literals and `WITH`-prefixed writes. A full MySQL parser would be a large dependency for a
guarantee privileges already give. The allow-list exists for friendly errors only.

## Testing

```sh
go test ./...                     # unit tests; MySQL tests skip

docker compose up -d --wait
MYSQL_TEST_DSN='mcp_ro:mcp_ro@tcp(127.0.0.1:3316)/demo' \
MYSQL_TEST_ROOT_DSN='root:root@tcp(127.0.0.1:3316)/demo' \
go test -race ./...               # plus integration and end-to-end tests
```

| Level | Where | What it covers |
|-------|-------|----------------|
| Unit | `internal/guard`, `config`, `audit`, `db`, `tools` | allow-list, grant parser, config, audit lines, value conversion, tool handlers against a fake store |
| Integration | `internal/db` | grant check as `mcp_ro` and root, schema queries, row cap, timeout, crafted writes |
| End-to-end | `cmd/mysql-mcp` | the real startup path over an in-memory MCP client, and the built binary over stdio |

CI runs all three against a MySQL 8.0 service container
([`.github/workflows/test.yml`](.github/workflows/test.yml)).

## Layout

```
cmd/mysql-mcp/      startup: config, connect, grant check, serve stdio
internal/config/    environment variables and defaults
internal/guard/     AllowedStatement and CheckGrants — pure, no database
internal/db/        Open, Grants, ListTables, DescribeTable, ReadOnlyQuery
internal/tools/     the three MCP tools and their JSON contract
internal/audit/     JSON-lines audit log
testdata/seed.sql   sample schema, generated rows and the read-only user
```

## Scope

Tested with MySQL 8.0. `START TRANSACTION READ ONLY` and `MAX_EXECUTION_TIME` also exist in
5.7, but 5.7 is not tested. Not included: HTTP transport or hosting, authentication, Postgres,
write tools, and per-table allow-lists.
